# Scenarios

| **Scenario ID** | **Scenario Name**                              | **Primary Actor**       | **Scenario Description** |
| --------------- | ---------------------------------------------- | ----------------------- | ------------------------ |
| **S-01**        | Applicant Booking a Driving Test              | Applicant               | An applicant logs into the system and searches for available test slots in their area; they select a slot for Monday at 12:00 pm. The system checks real-time availability and ensures there are no existing conflicts; it then reserves the booked slot, and the applicant receives a confirmation message. |
| **S-02**        | Applicant Rescheduling a Booking              | Applicant               | An applicant realizes they have other commitments on Friday, the day a previous driving test was booked; they navigate to “My Bookings,” delete the initial booking, and select a new available slot. The booking system releases the original slot back into the pool and sends a confirmation for the new booking, notifying the applicant of the change. |
| **S-03**        | Examiner Submitting a Pass/Fail Result        | Examiner                | After conducting a driver's test, the examiner logs into the system and accesses their dashboard. They locate the applicant's test records and submit a “Pass” alongside a few notes. The system then updates the applicant record and checks the booking as completed. Finally, the applicant receives a notification that their results are available. |
| **S-04**        | Administrator Assigning an Examiner a Test Slot | Administrator          | An administrator goes through the newly confirmed bookings and identifies an unassigned test slot. Using the admin dashboard, they select an available examiner based on location and schedules and assign them. Booking records are updated, and the examiner is notified. |
| **S-05**        | System Preventing a Double Booking            | Applicant and System   | Two applicants both try to book a slot at 9:00 am. The system applies an automatic database-level lock, allowing the first applicant to book and immediately marking it unavailable. The other applicant receives an error message, followed by a prompt to select another time. |
