# Core Processes Matrix

| **Process No. and Name** | **Input Data** | **Output Data** | **Rules** |
| --- | --- | --- | --- |
| P1 – Manage Accounts (1.0) | Account Details from Applicant (registration details, login credentials, profile edits, password-reset request) | Account Details stored in D1 Users | 1. An applicant must register before booking, viewing results, or requesting a certificate.<br>2. Mandatory fields (name, ID number, contact details, credentials) must be filled in.<br>3. The ID number must be unique. A duplicate registration is rejected.<br>4. Email and phone formats are validated before saving.<br>5. Credentials are stored securely (hashed), and the account is created only after validation passes. |
| P2 – Reserve Test Slot (2.0) | Booking Request (from Applicant); Slot List (from D3 Test Slots) | Available Slots and Booking Confirmation (to Applicant); Slot Update (to D3); New Booking (to D2 Bookings) | 1. Only a registered, logged-in applicant can request a booking.<br>2. Only slots marked available and in the future are shown.<br>3. A slot can be booked by one applicant only. The slot is marked "booked" in D3 as soon as the booking is confirmed, which prevents double booking.<br>4. An applicant cannot hold more than one active booking for the same test type.<br>5. The booking is saved with status "Confirmed" and a unique booking reference. The confirmation is sent only after both D2 and D3 are updated. |
| P3 – Manage Bookings (3.0) | View Booking Request and Cancel Booking Request (from Applicant); View/Filter Booking Request (from Administrator); Booking Data (from D2) | Booking Details and Cancellation Notification (to Applicant); Bookings (to Administrator); Status Update (to D2); Released Slot (to D3) | 1. Applicants can only view and cancel their own bookings.<br>2. A booking can be cancelled only if its status is "Confirmed" and the test is more than the minimum notice period away (e.g., 24 hours).<br>3. A cancelled booking is updated to "Cancelled" in D2, and its slot is released back to D3 as available.<br>4. A cancellation notification is sent after the status update is saved.<br>5. Administrators can view all bookings and filter them by date, status, applicant, or examiner.<br>6. A completed or past booking cannot be cancelled. |
| P4 – Assign Examiners (4.0) | Availability Information and View Scheduled Tests Request (from Examiner); Examiner Assignment and View Examiner Availability Request (from Administrator); Availability List (from D4); Booking List (from D2) | Schedule (to Examiner); Examiner Availability (to Administrator); Availability Record (to D4); Assignment (to D2 Bookings) | 1. Examiners submit the dates and times they are available, and these are stored in D4.<br>2. Only an administrator can assign an examiner to a booking.<br>3. An examiner can be assigned only to a booking that falls within their recorded availability.<br>4. An examiner cannot be assigned to two bookings at the same time.<br>5. The assignment is written back to the booking in D2 so that the examiner's schedule reflects it.<br>6. An examiner can view only their own scheduled tests. |
| P5 – Process Results (5.0) | Test Results (from Examiner); View Result Request and Certificate Request (from Applicant); Completed and Test Time (from D2); Results Data (from D5) | Result Response and Certificate Response (to Applicant); Test Results (to D5 Results) | 1. Only the examiner assigned to a booking can submit its result, and only after the test time has passed and the booking is marked "Completed".<br>2. Each booking can have only one result. Corrections require a re-submission by the assigned examiner.<br>3. Results must be recorded as Pass or Fail, and required fields (score or remarks) must be complete.<br>4. Applicants can view only their own results.<br>5. A certificate is issued only when the result is "Pass". A certificate request for a "Fail" or missing result is rejected with an explanatory message. |
