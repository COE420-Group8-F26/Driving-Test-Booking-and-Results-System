# Selected Use Cases – Lab 6 Sequence Diagram Modeling

| Use Case ID | Use Case Name | Primary Actor | Purpose | Reason for Selection |
|---|---|---|---|---|
| UC-01 | Log In | Applicant, Examiner, Administrator | A registered user enters their email and password. The system verifies whether the account is locked and if the password is entered accurately. If the credentials are valid, the failed-login counter is reset, an active session is generated, and the user is redirected to the dashboard for their specific role. However, if the password is incorrect, the failed-login count increments, and the account locks for 15 minutes after 5 consecutive failures. | For every other use case, Log In is a mandatory precondition; therefore, the rest of the system depends on it. It enforces security requirements for authentication, account lockout, and role-based redirection. The repeated attempts and nested pass/fail/lock conditions make it suitable for guard modeling and iteration. |
| UC-03 | Book Test Slot | Applicant | An authenticated applicant selects an available test slot. The system checks that the slot is still available, that the applicant has no conflicting booking, and that the test starts at least 30 minutes later. If the request is valid, the system reserves the slot, creates a confirmed booking with a unique reference number, notifies the applicant, and logs the action. Otherwise, it rejects the request and gives the reason. | Booking is the entry point of the whole system, since every later step (examiner assignment, testing, results) depends on a confirmed booking. It involves the most validation rules and rejection paths (cutoff, conflict, double-booking) and many collaborating objects, which makes it well suited to iteration and guard modeling. |
| UC-05 | Assign Examiner to Booking | Administrator | An authenticated administrator assigns an available examiner to a confirmed booking that has no examiner. The system updates the booking record, notifies the examiner and logs the action. | Assigning an examiner is a core function of the system because a confirmed booking cannot be tested or graded until an examiner is assigned. It links the booking process to the examiner scheduling and results process. |
| UC-07 | Submit Test Result | Examiner | An authenticated examiner submits a pass or fail result for an assigned driving test after its scheduled time. The system records the result and submission timestamp, marks the booking as completed, updates the applicant's record status, and notifies the applicant that the result is available. | Result submission is a core function of the system. It involves validating the examiner's assignment and the test time before recording a result. It also supports conditional interactions based on the pass or fail outcome, making it suitable for demonstrating guards and alternative flows in a sequence diagram. |
